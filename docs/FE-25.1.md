# FE-25.1 · NPCS-44 · Mostrar y editar la asignación (H25)

Fuente: [FE-25.1 en Jira](https://uca-team-zec8wzmz.atlassian.net/browse/NPCS-44).
Ruta: `/organizador/calendario`, detalle de cada partido.

## Comportamiento

La tarjeta muestra el árbitro actual (o Sin asignar) y, solo para partidos
PROGRAMADO, ofrece Cambiar árbitro / Asignar árbitro. Al abrir el editor consulta
los candidatos disponibles para ese partido; no usa el catálogo general como
prueba de disponibilidad. La lista incluye al actual si sigue siendo elegible.
Lista vacía, carga y error se muestran explícitamente; los errores de consulta
permiten reintentar. Cancelar cambio no escribe nada.

Al guardar, bloquea los controles del calendario y los envíos repetidos. Solo
confirma tras una respuesta válida del backend, muestra el nombre confirmado y
vuelve a consultar el calendario. No cambia la asignación de forma optimista.
Ante 409 conserva el asignado y actualiza los candidatos; una selección que ya
no aparece deja de ser válida. Ante 404/422 también actualiza candidatos.
La disponibilidad es informativa hasta que PUT la valida de nuevo en servidor.

`RutaProtegida` impide montar el calendario sin rol ORGANIZADOR; las acciones
verifican sesión y rol mediante `calendarioApi`. El estado del editor es local y
no se amplía AuthContext. No permite editar partidos en curso, finalizados o
cancelados, ni consulta sus candidatos.

## Contrato de BE-25.1

- GET `/api/v1/partidos/{id}/arbitros-disponibles` →
  `{partidoId, arbitros: [{id, nombre}]}`; petición `cache: no-store`.
- PUT `/api/v1/partidos/{id}/arbitro`, JSON `{arbitroId}` →
  `{partidoId, arbitroId, arbitroNombre}`.
- IDs de partido positivos de 32 bits y UUID validados antes de enviar.
  Se valida la identidad del partido y árbitro de la confirmación.
- Se conserva el código y mensaje del backend: 401, 403, 404, 409, 422.
  El token permanece en servidor. PUT solo envía arbitroId; no modifica horarios,
  cancha, equipos o estado.
- El backend decide actividad, cruces de horario y concurrencia y revoca los
  permisos del árbitro anterior. No se reproduce esa lógica en el cliente.
